====================================================
Функциональная спецификация приложения "Кситал"
====================================================

:version: 2.6
:date: 2025-05-11
:platform: Android 6.0 (API 23) — Android 14+ (API 34)

-----------------------
1. Общее описание
-----------------------

Приложение "Кситал" предназначено для управления удалённым устройством (далее – Устройство) через SMS-сообщения. 
Приложение работает только в активном режиме (при открытом экране), не выполняя фоновых операций. 
Все управляющие команды и ответы Устройства передаются через SMS.

**Важно:** На Android 14 и выше (API 34+) вкладка "Статус" скрыта, чтение SMS и автоматическое обновление состояния не производятся из-за ограничений безопасности. Приложение на этих версиях работает только как пульт управления (отправка команд) и настройки.

-----------------------
2. Архитектура и ограничения
-----------------------

- Платформа: Android 6.0 (API 23) и выше.
- Язык реализации: Java.
- Сборка: системный Gradle (не gradlew), подписанный release APK.
- Не используется постоянное хранилище для статусов – данные извлекаются из входящих SMS при каждом открытии экрана "Статус" (только на Android <14).
- Отсутствует поллинг – новые SMS обрабатываются через динамический BroadcastReceiver, активный только когда приложение на экране.
- Приложение не работает в фоне: после сворачивания все операции (включая ресивер) прекращаются.

-----------------------
3. Экран "Статус" (только на Android <14)
-----------------------

3.1. Назначение
    Отображение наиболее актуальных параметров Устройства, полученных из SMS-сообщений.

3.2. Отображаемые показатели
    +------------------------+-----------------------------------+
    | Название               | Формат / Пояснение                |
    +========================+===================================+
    | Напряжение             | "есть" (зелёный) / "нет" (красный)|
    +------------------------+-----------------------------------+
    | Текущая температура    | число с плавающей точкой, °C      |
    +------------------------+-----------------------------------+
    | Требуемая температура  | целое число, °C (диапазон 5–40)   |
    +------------------------+-----------------------------------+
    | Последний баланс       | число с плавающей точкой, " р."   |
    +------------------------+-----------------------------------+
    | Верхний порог оповещения| целое число, °C                   |
    +------------------------+-----------------------------------+
    | Нижний порог оповещения | целое число, °C                   |
    +------------------------+-----------------------------------+
    | Последнее обновление   | дата/время самого свежего ответа  |
    +------------------------+-----------------------------------+

    Если какой-либо показатель неизвестен (нет сообщения), отображается длинное тире "—".

3.3. Обновление данных
    - При запуске приложения (onResume) считываются все SMS-сообщения, связанные с номером Устройства, от новых к старым до получения всех показателей.
    - При переключении на вкладку "Статус" (onResume фрагмента) также выполняется повторное считывание.
    - Новые сообщения, поступившие в активном состоянии, отслеживаются через BroadcastReceiver. При обнаружении новых данных информационная строка мигает красным цветом один раз.

3.4. Информационная строка
    - В обычном режиме показывает дату самого старого из отображаемых показателей ("По состоянию на ...").
    - При ожидании ответа на запрос статуса показывает "Ожидание общего статуса...", на запрос баланса – "Ожидание актуального баланса...".

-----------------------
4. Экран "Управление"
-----------------------

4.1. Команды
    - **Запросить статус** – отправка SMS вида `Kak dela? <пароль>`
    - **Установить требуемую температуру** – диалог ввода целого числа от 5 до 40. 
        *При попытке установить температуру ниже 10°C появляется диалог предупреждения: «Температура ниже 10°C может привести к нежелательным последствиям. Продолжить?»*
      Отправка SMS вида `Temp.R=XX <пароль>`
    - **Запросить баланс** – отправка SMS вида `Balans? <пароль>`
    - **Удалить старые сообщения** – открывает диалог выбора срока в днях (опции: 0, 90, 30, 60, 180, 365, 7, 14). При выборе 0 дней удаляются ВСЕ сообщения, связанные с номером Устройства. При выборе другого значения – сообщения старше указанного количества дней.

4.2. Особенности отправки
    - Команды отправляются немедленно, без очередей и проверок частоты.
    - Используется SIM-карта, выбранная в настройках.
    - После отправки запроса статуса или баланса приложение переходит в состояние ожидания ответа (информационная строка обновляется).

-----------------------
5. Экран "Настройки"
-----------------------

5.1. Параметры
    - **Номер телефона Кситал** – выбирается из контактной книги устройства.
    - **SIM-карта для отправки** – список доступных SIM-карт; кнопка обновления.
    - **Управляющий пароль** – текстовое поле (1–5 цифр), маскировка звёздочками, кнопка показа.

5.2. Сохранение
    - Все настройки сохраняются в `SharedPreferences`.
    - После сохранения (если Android <14) принудительно читаются SMS и открывается вкладка "Статус". На Android 14+ вкладка "Статус" отсутствует, но настройки сохраняются.

-----------------------
6. Обработка SMS (только Android <14)
-----------------------

6.1. Чтение
    - При активном экране "Статус" и наличии всех разрешений запускается BroadcastReceiver.
    - Каждое новое SMS обрабатывается мгновенно.
    - При первом открытии или возврате в приложение выполняется полное сканирование истории сообщений (до получения всех показателей).

6.2. Форматы сообщений (парсинг)
    +------------------------------------------+-------------------------------------+
    | Тип сообщения                            | Поля для извлечения                 |
    +==========================================+=====================================+
    | Пропало напряжения                       | voltage = false                     |
    | `Propalo naprjagenie 220V` либо          |                                     |
    | `Naprjagenie propalo`                    |                                     |
    +------------------------------------------+-------------------------------------+
    | Восстановлено напряжения                 | voltage = true                      |
    | `Vosstanovleno 220V!` либо               |                                     |
    | `Naprjagenie vosstanovleno`              |                                     |
    +------------------------------------------+-------------------------------------+
    | Системное сообщение о порогах            | upperThreshold, lowerThreshold,     |
    | `systema KSYTAL- ... Temp.H=+AA ...`     | requiredTemperature                 |
    +------------------------------------------+-------------------------------------+
    | Баланс                                   | balance (float)                     |
    | `205.48 р.` (с последующим текстом)      |                                     |
    +------------------------------------------+-------------------------------------+
    | Полный статус                            | currentTemperature (из поля `T1=`), |
    | `T1=+14,5C; T2=...`                     | voltage (по наличию                 |
    | `Naprjagenie norma.` => напряжение есть  | `Naprjagenie norma`),               |
    | `Naprjagenie propalo` => нет             | requiredTemperature (из `Temp.R=`)   |
    +------------------------------------------+-------------------------------------+

6.3. Форматы запросов
    - Запрос статуса: `Kak dela? <пароль>`
    - Запрос баланса: `Balans? <пароль>`
    - Установка температуры: `Temp.R=XX <пароль>` (XX – двузначное число)

-----------------------
7. Удаление сообщений (особенности на Xiaomi/Redmi)
-----------------------

7.1. Проблема
    На прошивках MIUI (Xiaomi, Redmi) даже при предоставлении разрешения `WRITE_SMS` стандартным способом реальное право `appops` часто остаётся запрещённым.

7.2. Решение в приложении
    - Приложение проверяет `AppOpsManager` и, если необходимо, показывает инструкцию по ручному включению переключателя «Запись SMS» в настройках приложения.
    - На устройствах без дополнительных ограничений удаление работает через `ContentResolver`.

7.3. Альтернатива (ADB)
    Для единоразового удаления можно выполнить команду через ADB (требуется включённая отладка по USB):
    `adb shell appops set com.ksytal.app WRITE_SMS allow`

-----------------------
8. Логирование
-----------------------

- Для отладки используются логи с тегом `KsytalCleaner` (процесс удаления) и общие логи приложения.
- Просмотр логов: `adb logcat -s KsytalCleaner`

-----------------------
9. Сборка и установка
-----------------------

- Скрипты сборки используют системный Gradle (не обёртку).
- Имена выходных APK: `ksytal-debug.apk` и `ksytal-release.apk`.
- Для установки используется `adb install`.
- Версии кода и имени обновляются в `app/build.gradle`.
- Release-версия подписывается собственным keystore (`~/.android/ksytal.keystore`).

-----------------------
10. Поведение на Android 14+ (API 34)
-----------------------

- Вкладка **«Статус»** полностью скрыта из интерфейса.
- **Чтение SMS и автоматическое обновление состояния не выполняются**.
- Приложение работает только как пульт управления: доступны вкладки «Управление» и «Настройки».
- Отправка команд (запрос статуса, установка температуры, запрос баланса) и удаление сообщений **работают без изменений** (но удаление может требовать дополнительных прав, как описано в разделе 7).
- Пользователю рекомендуется для получения информации об устройстве использовать команду «Запросить статус» и читать ответное SMS в стандартном приложении сообщений.
